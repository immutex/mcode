# 0.1.0 Batch — Usable Product

> TL;DR: 0.1.0 finishes what 0.0.x started. The dominant defect is not missing
> code but **built-and-unwired** code: eleven interfaces exist with either no
> producer or no caller. This batch wires them, ships the seven first-party
> extensions `23` mandates, and adds the five subsystems that make mcode a daily
> driver — LSP diagnostics, background jobs, image input, MCP resources/prompts,
> and ACP.

## Why this batch exists

`0.0.4` was a quality pass and left the tree clean but honest about its gaps: no
LSP anywhere, one eval fixture where `11` asks for 30–100, and the `23` shipping
table four extensions short of its own list. The `0.0.x` batches built the
**interfaces** for most of the remaining capability — the extension API, the
subagent primitives, the pinned state block, the MCP transport layer — and then
did not connect them. That is the cheapest possible starting point, and it is
also the easiest thing to mistake for done: every one of those interfaces has a
test that passes against a stub.

So the work splits into wiring (high value, low risk, mostly small) and new
subsystems (genuinely new code).

## The defect class: built, not wired

Every row was verified by reading the code, not inferred. "Producer" means
something that writes the value; "caller" means something that reads it.

| # | Interface | Producer | Caller | Consequence today |
|---|---|---|---|---|
| 1 | `install_request::commands` | none | none | `mcode.cmd.register` **raises** in a real session |
| 2 | `install_request::http_client` | none | none | `mcode.net.get/search` return `nil` — **no network from any extension** |
| 3 | `install_request::session_state` | none | none | `mcode.session.snapshot/fork` return `nil` |
| 4 | `install_request::instruction_sink` | none | none | `mcode.context.add_instructions` returns `nil` |
| 5 | `install_request::skill_sink` | none | none | `mcode.skill.register` returns `nil` |
| 6 | `install_request::deferred` | none | none | `mcode.defer` **raises** |
| 7 | `invoke_command` | n/a | **none** | a registered command is unreachable; the palette is a static list |
| 8 | `pinned_state::plan` | **none** | none | `render_pinned_state` has no production caller — the block is never injected, so there is no recitation and no plan field |
| 9 | `run_subagent` | n/a | **none** | delegation is implemented and unreachable; there is no `task` tool |
| 10 | `model.tier.plan/act/side` | n/a | **none** | tiering is documented in `15` and read by zero lines |
| 11 | `session_forker` | none | none | session branching (`04` §Session branching) is unimplemented end to end |

Rows 1–6 share one root cause: `default_register_api` (`loader.cxx:357`)
constructs `install_request` with nine collaborators omitted, and both CLI call
sites (`cli/commands.cxx:246`, `cli/session.cxx:200`) go through it. One struct
extension and two call sites fix all six.

## Wave 0 — wire what exists

Ordered by leverage. Each unblocks the next.

1. **`register_context` carries the missing collaborators.** Add `commands`,
   `session_state`, `session_forker`, `http_client`, `web_searcher`, `notifier`,
   `deferred`, `instruction_sink`, `skill_sink`; populate them at both CLI call
   sites and in the smoke harness. Unblocks rows 1–6.
2. **Extension commands reach the palette.** `invoke_command` gains its caller:
   registered commands merge into `builtin_commands`, and `run_command` falls
   through to the extension registry for an unknown name. Unblocks row 7, and is
   the mechanism a user-defined `/command` needs.
3. **The pinned state block is produced and injected.** `pinned_state` gains a
   plan producer (from session state, so it survives the `todo` extension being
   disabled — `04` requires recitation to read session state, not the extension)
   and `render_pinned_state` is injected into the request tail. Unblocks row 8
   and is the storage the `todo` tool writes.
4. **The `task` tool.** A bundled extension over `run_subagent` (`23` makes the
   spawn primitives core and the tool shell an extension), with the child budget
   **carved from the parent** rather than a fresh 2M/5 USD — `04` §Budget
   accounting requires the parent to decrement by child spend. Unblocks row 9.
5. **Model tiering.** Resolve `model.tier.plan|act|side` and route by call site:
   the loop tags each request, and the `side` tier owns compaction and titling.
   Unblocks row 10. Fall back to `model.model` when a tier is unset.

## Wave 1 — the seven first-party extensions

`23` names the shipping set; four exist (`providers`, `memory`, `skills`,
`deepseek-guard`). The rest are the dogfooding test for the API, so they are
built **only** against the public `mcode` surface — no private escape hatch.

| Extension | Tools | Depends on |
|---|---|---|
| `fs-extra` | `todo` | Wave 0 item 3 (session state) |
| `web` | `web_search`, `fetch` | Wave 0 item 1 (network) |
| `git` | `git_status`, `git_diff`, `git_commit` | a gated exec API for Lua (below) |
| `github` | `gh_pr`, `gh_issue`, `gh_review` | the same exec API |

**The one new core API this requires: `mcode.bash( command, opts )`.** `23` says
`git` demonstrates "composing `bash`", but no Lua-callable exec entry point
exists, and it must not become one that bypasses the gate — `bash` is core
precisely because it owns the sandbox, the permission engine and the PTY
(`06`). So the new entry point routes to the *same* core handler with the same
permission checks, declared under a `process` manifest permission, and a
manifest that does not declare it cannot call it. This is a security-relevant
addition and gets its own trap entry.

## Wave 2 — new subsystems

| # | Feature | Shape |
|---|---|---|
| L | **LSP diagnostics and navigation** | New `Content-Length`-framed transport behind the existing `transport` interface; `jsonrpc` and `supervisor` reuse. Diagnostics attach to the `edit`/`write` tool result (zero always-loaded schema); a thin `lsp` tool covers definition/references/hover. Servers come from `PATH` via `[lsp]` config — nothing is bundled. |
| B | **Background jobs** | `bash` gains a detached mode; a job registry holds handles; the event bus carries completion; a `job` tool polls or waits. |
| M | **Image input** | `message` gains content parts; `render` emits the provider's image shape; the editor accepts a pasted image path. |
| P | **MCP resources and prompts** | `resources/list`, `resources/read`, `prompts/list`, `prompts/get` on the existing client; resources surface as a tool, prompts as slash commands. |
| C | **OSC 52 clipboard** | Emit and read the escape sequence; the editor's paste path accepts an image and a text selection. |

## Wave 3 — integration

| # | Feature | Shape |
|---|---|---|
| A | **ACP editor integration** | JSON-RPC over stdio on the same `jsonrpc` module; a session as an agent endpoint. Protocol, not a GUI. |
| S | **Session sharing and export** | Extend `/export`; a shareable transcript without absolute paths or credentials. |

## Wave 4 — verification

1. **Grow the eval fixture suite** from 1 repo toward `11`'s 30–100, each with a
   known-broken state and an exact expected outcome. This is what makes every
   claim above measurable rather than asserted.
2. **The anti-reward-hacking checklist** (`11`): `hack_flags` on every run, the
   `git diff` audit for test edits, and the recorded fail-before/pass-after pair.
3. All gates: `ctest`, `--smoke`, `_clgate.py`, the ConPTY TUI gate, the comment
   linter, `eval`, and a real turn against a live provider.

## Order and dependencies

```
Wave 0.1 register_context ─┬─> 0.2 extension commands ──> Wave 1 git/github (via bash API)
                           ├─> 0.3 pinned state ──> Wave 1 fs-extra (todo)
                           ├─> 0.4 task tool
                           └─> 0.5 tiering
Wave 1 web ──> (needs 0.1)
Wave 2 L / B / M / P / C  ── independent of each other, all after Wave 0
Wave 3 A / S              ── after Wave 2 (A reuses the jsonrpc module)
Wave 4                    ── continuously, and again at the end
```

`0.1` is the critical path: six of the eleven defects close with it, and two
Wave 1 extensions cannot exist without it.

## Acceptance for 0.1.0

- All eleven defects closed, each with a test that fails against the old code.
- Seven first-party extensions present, loading, and exercising the public API.
- The five Wave 2 subsystems work end to end on Windows, with POSIX paths
  verified by `_clgate.py` and CI.
- The eval suite runs ≥30 fixture repos and reports `hack_flags`.
- No budget regression: cold start ≤15 ms, idle RSS ≤30 MB, binary ≤25 MB,
  always-loaded schema ≤3K tokens.
- `AGENTS.md`, `docs/00-index.md`, `README.md` and the `CHANGELOG.md` updated in
  the same change.

## Traps

- **A stub that satisfies a test is not a wired interface.** Every row in the
  table above has a passing test. The check that matters is a call site, and the
  test that matters is one that fails when the collaborator is absent.
- **`mcode.bash` must not become a bypass.** It routes to the core handler and
  is gated by the manifest permission; a Lua socket is still impossible.
- **The pinned state must survive its extension.** Recitation reads session
  state, so disabling `fs-extra` loses the `todo` *tool*, not the plan.
- **LSP diagnostics are untrusted input.** They are text from a third-party
  process and go into the model's context, so they carry the same delimiting and
  size caps as any other tool result.
- **A language server is a child process.** It needs the sandbox and egress
  treatment every other spawn gets; it is not exempt because it is "ours".
